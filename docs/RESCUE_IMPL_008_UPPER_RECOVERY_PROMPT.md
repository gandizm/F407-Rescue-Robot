# RESCUE-IMPL-008 第 4 项：上位机恢复合同待确认 Prompt

以下内容可直接转发给上位机同学。请先完成双方确认，再实现或部署；本文件不占用新 opcode，也不代表恢复动作已经实现。

```text
请确认安全区二次推送失败后的恢复合同，未确认前不要改代码或现场使用：

1. 计时责任：二次推送完成后由谁发出“阶段完成”事件？推荐由 F407 在
   “后退10 mm + 前进50 mm/S1从85°到55°”真实完成后报告明确的阶段状态，
   由 RDK 从收到该状态的时刻开始计 5 s。不能从开爪、进入安全区或首次
   ENTER_SAFE_ZONE 开始计时。

2. 超时责任：推荐 RDK 作为唯一超时判定方；5 s 内没有现有视觉确认（当前
   真实成功仍是既有视觉窗口，不能用编码器、轮空转或 mode15 代替），RDK
   才能发恢复请求。F407 不自行猜测超时，也不能把恢复完成报告成投送成功。

3. 命令与反馈：当前 RAM_VERIFY 没有可直接执行横移恢复的现成授权；请双方
   明确是新增独立 recovery opcode，还是扩展现有协议字段，并约定：请求的
   ACK、执行中状态、完成状态、ABORT/硬故障优先级、超时/拒绝反馈。未选定
   前不要复用 TASK_COMPLETE、RETURN_CENTER、CHANGE_LANE 或任意旧动作偷渡。

4. 几何与坐标：恢复动作的推荐物理意图是 S1 先到55°，再沿“远离中隔板”
   的目标半区方向横移 200 mm（20 cm），随后回中心。200 mm 只是用户估计，
   不能保证任何姿态、载荷或障碍下必然脱离；必须明确方向来源和坐标系：
   上位机应传锁存批次的目标半区/带符号方向，或传已完成车体变换的横移
   量。F407 不得从红蓝颜色臆猜左右，也不得把 heading 当横向位置误差。

5. 业务结果：恢复完成不等于投送成功。RDK 不得发送 TASK_COMPLETE，不得
   增加 delivery_count，不得置 first_common_delivered，不得加分。请确认
   恢复后该批次是保留并允许一次重试、标记未确认后继续搜索，还是终止该
   批次；并明确对应的状态清理和下一条命令。

6. 待双方确认的推荐默认值：RDK 判定 5 s 超时；RDK 发独立 recovery 请求；
   F407 ACK 后执行并回报真实完成；任何视觉成功仍走原确认链；ABORT、硬故障、
   通信失效停车优先于恢复动作。请逐项回复“确认/修改”，再确定协议。
```

当前实现边界：本轮只实现已批准的启动连续运动和二次推送；第 4 项没有写恢复执行代码、没有预留 opcode、没有改变成功判定。
