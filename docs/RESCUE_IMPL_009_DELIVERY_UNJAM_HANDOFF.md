# RESCUE-ADAPT-009：投送失败退料接口交接

本文件描述 F407 已实现、但当前上位机 `9c996f9` 尚未发送的独立退料接口。
它不代表上位机已经接入，也不触发 F407 自己的 5 s 失败判定。

## 协议占用核对

- `TYPE=0x18` 任务命令当前使用 `0x00`、`0x02..0x12`；`0x13` 在现有
  `VisionMissionCode` 中未占用，本接口使用 `DELIVERY_UNJAM=0x13`。
- 普通状态值已使用 TaskState `0..18、24、25`，完成反馈已使用 `30..36`；
  `37` 当前未占用，本接口使用 `DELIVERY_UNJAM_DONE=37`。
- 不复用 `CHANGE_LANE=0x11`，也不复用 `mode=36`。执行中沿用公共
  `mode=25`，只是远程动作类型独立。

## 命令帧

仍使用现有 15 字节 `TYPE=0x18` 帧和原有 CRC/SEQ 规则：

| 字段 | 值/含义 |
|---|---|
| `P0` | `0x13 DELIVERY_UNJAM` |
| `P1` | 仅 `VALID=0x01`；不带阵营位、`DRIVE_STRAIGHT`、`USE_FINAL_HEADING` 或 `DISTANCE_VALID` |
| `P2/P3` | 有符号 `int16`，单位 mm，必须为 `+200` 或 `-200`；正值=车体物理左，负值=车体物理右 |
| `P4/P5` | `0`，保留 |
| `P6/P7` | `0`，保留；不传航向 |
| `SEQ` | 每次新请求递增；重复新 SEQ 只 ACK，不重做当前动作 |

横移方向由上位机根据已锁存批次的目标半区和当前车体姿态计算并编码；F407
不根据红蓝阵营猜左右，也不把 `CHANGE_LANE` 当作本请求的别名。

## 合法上下文与动作

F407 只在新鲜 `TASK_RAM_VERIFY/mode=15`、双爪已打开的投送观察阶段接受该命令。
固定上位机 `9c996f9` 不会发送它；F407 不自动进入该动作，也不自行计 5 s。

接受后：

1. ACK 请求，进入公共执行 `mode=25`；
2. 发出 S1=55°，非阻塞等待 500 ms。该等待是机械抬升稳定窗口，不是动作
   失败超时，不新增锁停；
3. 使用现有车体横移/编码器进度执行带符号 200 mm；
4. 到位停车并报告 `mode=37 DELIVERY_UNJAM_DONE`，保持 S1 抬起，等待上位机
   发送 `RETURN_CENTER`。

动作完成不等于投送成功：F407 不发送或伪造 `TASK_COMPLETE`，不置
`first_delivery_done`，不产生成功标记。收到 `RETURN_CENTER` 后沿现有返中流程
进入 `FACE_FIELD_CENTER/mode=17`，真实返中完成后按现有逻辑恢复 S1=85°并回到
`SEARCH`。动作暂停后，同一命令只续作，不重置已完成的横移；下一批进入新的
`mode=15` 后可以再次触发。

## 可直接转发给上位机同学的 Prompt

```text
请接入 F407 的投送失败退料接口，但不要在固定上位机 9c996f9 流程中自行触发：

1. 由上位机下一轮在自己的失败观察窗口结束后判定失败，再发送 TYPE=0x18 的
   DELIVERY_UNJAM=0x13。F407 不自行计 5 s，也不自动横移。
2. 帧字段固定为：P1=VALID(0x01)；P2/P3=有符号横移距离 +200 或 -200 mm；
   正值表示车体物理左、负值表示车体物理右；P4/P5/P6/P7 全为0。方向由
   上位机按目标半区和当前车体姿态确定，F407 不猜左右。CRC/SEQ 沿用现有协议。
3. 只在投送观察合法上下文发送，并等待新鲜 mode=25；F407随后抬S1到55°、
   非阻塞等待500 ms，再执行带符号200 mm横移，完成后报告独立 mode=37。
   mode=37 不是投送成功、不是 TASK_COMPLETE、不是 mode=36 换道完成。
4. 收到 mode=37 后，发送 RETURN_CENTER；不要发送 TASK_COMPLETE。恢复动作完成
   后仍由上位机决定保留批次重试、标记未确认或继续搜索；任何真实投送成功仍走
   原有视觉确认链。
5. F407 对同一执行中的重复新 SEQ 只 ACK 不重做；暂停后续作，不把已完成位移
   清零。当前 9c996f9 未发送 0x13，因此没有兼容旧命令的自动 fallback。
```
